## What this repository is

A [Blume](https://useblume.dev) documentation site (`blume` npm package, currently v1.0.4). Blume is a
markdown-first docs framework built on Astro/Vite: this repository holds only content and
configuration — there is no app code to maintain. The CLI (`npx blume ...`) generates and drives a
hidden Astro project under `.blume/` at dev/build time; that directory is generated output, never
edit it directly (it is excluded from `.gitignore` review only insofar as it's regenerated — treat it
as build output).

## Commands

```bash
npm install      # install dependencies
npm run dev      # blume dev — dev server with hot reload (default: http://localhost:4321)
npm run build    # blume build — static HTML + local search index to dist/
npm run doctor   # blume doctor — diagnose config/content problems
```

There is no lint or test suite — this is a content-only project. Verify changes by running `npm run
dev` and checking the rendered page (or `curl`/a headless browser against `localhost:4321`).

## Structure

- `docs/` — the actual content. Every `.md`/`.mdx` file becomes a page; navigation is inferred from
  the file tree (refine it with `meta.ts` files or config if the structure grows beyond the single
  `docs/index.mdx` that exists today).
- `blume.config.ts` — site-wide config: `title`, `description`, and `theme` (accent color, corner
  `radius`, and font roles for `display`/`body`/`mono`, set via `defineConfig`). Real TypeScript,
  validated by a schema.
- `public/images/` — static image assets referenced from MDX via absolute paths (e.g.
  `/images/cover-vermeer-original.jpg`).
- `.blume/` — generated Astro project (dev server + build pipeline). Not source; regenerated by the
  CLI, safe to delete.

## Content authoring

Pages are Markdown/MDX with frontmatter (`title`, `description`) that Blume renders as the page
heading and intro automatically — do not duplicate the title as a manual `# Heading` in the body (it
creates a duplicate heading).

Built-in components are available in any `.mdx` file with **no imports** — `Card`/`CardGroup`,
`Badge`, `Steps`, `Tabs`, `Accordion`, `Columns`, `Frame`, `CodeGroup`, `Tile`, and more. Notably,
`Card` accepts an undocumented-in-prose but supported `img` prop (a path under `public/`) for a cover
image above the icon/title/blurb — used in this project's `docs/index.mdx` for the "Slab" card
gallery. The authoritative component reference (with live-preview source for every component) lives
in the installed package at `node_modules/blume/docs/content/components.mdx`; the full docs tree
(`node_modules/blume/docs/`) covers configuration, navigation, search, SEO, AI features, and theming
in more depth than is worth duplicating here.

Theming is token-driven (`--blume-*` CSS custom properties) and can be overridden further via a
`theme.css` at the project root, which layers on top of `blume.config.ts` tokens — see
`node_modules/blume/docs/configuration/theming.mdx` for the full token list.

## Known gotchas

- Full-page screenshots (Playwright `full_page=True` or similar) of the dev server can show a
  duplicated/overlapping sidebar on mobile viewport widths — this is a screenshot-stitching artifact
  from the sidebar's `position: fixed`, not a real rendering bug. Verify layout issues with a
  viewport-sized (not full-page) screenshot before treating them as real.
